# תפעול: הריצה הלילית, טוקן, שנה חדשה ותוכנית חדשה

לבעלי הריפו. איך מריצים ובודקים מקומית: [DEVELOPING](DEVELOPING.md).

## הריצה הלילית

**הריצה הלילית הראשונה:** המטמון של GitLab ריק בהתחלה, ומשיכה מלאה ארוכה מריצה אחת. `timeout 160m` עוצר את הסורק לפני ש-GitLab הורג את ה-job, המטמון נשמר (`when: always`), והריצה נחשבת חלקית: ירוקה, בלי commit. הריצה הבאה ממשיכה מהמטמון, ולכן משיכה ראשונה לוקחת 2-3 לילות. הריצה החלקית הרביעית ברצף נכשלת, כדי שסריקה תקועה תשלח מייל.

**דקות CI:** בחשבון החינמי של GitLab יש לקבוצה 400 דקות CI בחודש, גם לפרויקט ציבורי (מקדם 1; רק תוכנית GitLab for Open Source מורידה ל-0.5). ההשהיה בין בקשות נספרת כזמן ריצה. משיכת כל הקבוצות בכל לילה לקחה כ-20 דקות, כלומר כ-600 בחודש, ולכן כל קורס נמשך פעם בשני לילות: כ-11 דקות ללילה, כ-330 בחודש. הקבוצות באתר בנות יום או יומיים לכל היותר. הפרויקט `lets_learn-group/lets_learn-scrape` ציבורי, ולכן לוגי הריצות גלויים: הטוקן לא מודפס בהם, ומשתני ה-CI נשארים סודיים.

## חידוש GH_PUSH_TOKEN

הסריקה דוחפת ל-GitHub עם טוקן fine-grained שיש לו תאריך תפוגה. ה-job `token-expiry` ב-[ci/gitlab-scrape.yml](../ci/gitlab-scrape.yml) נכשל, ושולח מייל, כשנשארים פחות מ-14 יום, וגם כש-GitHub דוחה את הטוקן (פג או בוטל). הסריקה עצמה ממשיכה לרוץ. כדי לחדש:

1. ב-GitHub: Settings → Developer settings → Fine-grained tokens → Generate new token.
2. Repository access: רק `dolev-benezri/lets_learn`. Permissions: Contents, Read and write. לבחור תאריך תפוגה.
3. ב-GitLab, בפרויקט `lets_learn-scrape`: Settings → CI/CD → Variables → `GH_PUSH_TOKEN` → להדביק את הטוקן החדש (Masked and hidden, Protected).
4. Build → Pipeline schedules → ▶ כדי להריץ פעם אחת. ב-log של `token-expiry` מופיע התאריך החדש.
5. למחוק ב-GitHub את הטוקן הישן.

## מעבר שנת לימודים

האתר לוקח את השנה האקדמית מ-`catalog.json`, שהסורק כותב, והמטמון נשמר בתיקייה נפרדת לכל שנה (`.yedion-cache/2028`). כשהידיעון של השנה הבאה מתפרסם:

1. משנים את ברירת המחדל של `--year` ב-`scripts/scrape.mjs`.
2. ב-`scripts/programs.json`, לכל תוכנית: מוסיפים את המחזור החדש ל-`cohorts` ואת קודי הרשימות שלו ל-`lists`, ומורידים את המחזור הישן.
3. ב-`web/ics.js` מוסיפים ל-`SEMESTER_DATES` את תאריכי הסמסטרים ואת הימים בלי לימודים, מתוך [לוח השנה האקדמי](https://www.afeka.ac.il/about-afeka/general-information/academic-calendar/). בלי השורה הזו, כפתור הייצוא ללוח שנה כבוי.
4. מריצים `npm test` ומחכים לריצה הלילית. קישורי גיבוי מהשנה הקודמת ממשיכים לעבוד: הקורסים, הציונים וההעדפות נשמרים, ונעיצות, חברים ושיוך לסמסטר נמחקים. קישורי חבר מהשנה הקודמת נדחים.

## הוספת תוכנית

1. `node scripts/discover.mjs --cache cache --offline > draft.json` מפיק טיוטת הגדרות מהמטמון: מסלולים, מחזורים, רשימות והתמחויות.
2. מעתיקים את הטיוטה ל-`scripts/programs.json` ומשלימים ידנית את מה שלא מופיע באתר: `deptName` (מילת האוכלוסייה בדרישות הקדם), `anchor` (קורס שחייב להופיע בכל מחזור וסמסטר), `degree`, `specRule`, ולפעמים `minCourses` לתוכנית קטנה.
3. משאירים `verified: false` עד שכל שדה שמולא ביד נבדק מול תוכנית הלימודים הרשמית של התוכנית, ומוסיפים את הקישור אליה ל-[COVERAGE](COVERAGE.md).
4. מריצים `npm test` ו-`--offline` על המטמון, ובודקים בדפדפן.
5. `node scripts/audit.mjs` מדפיס סקירת נתונים אוטומטית (קורסי חובה שלא נפתחים, דרישות קדם שבורות, סכומי נ״ז). הדוח האחרון: [docs/DATA-AUDIT.md](DATA-AUDIT.md).
