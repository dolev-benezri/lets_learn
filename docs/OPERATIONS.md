# תפעול: מדריך למי שמחזיק את הכלי

הדף הזה לאדם או לצוות שמקבל את הכלי לידיים: איפה הוא רץ, איך מעדכנים אותו, ומה בודקים אחרי כל פריסה. ארבעת הסעיפים האחרונים (הריצה הלילית, טוקן, שנה חדשה, תוכנית חדשה) הם התפעול השוטף של בעלי הריפו.
איך מריצים ובודקים מקומית: [DEVELOPING](DEVELOPING.md). אבטחה ופרטיות: [SECURITY](SECURITY.md). מבנה הקוד: [ARCHITECTURE](ARCHITECTURE.md).

## אירוח

האתר הוא תיקיית `web/`: קבצי HTML, CSS ו-JavaScript (ES modules) וקובצי JSON. אין build, אין קוד שרת ואין מסד נתונים; כל מה שהמשתמש שומר נשאר ב-localStorage של הדפדפן שלו.

- **אפשר לארח בכל שרת קבצים סטטי.** מעתיקים את תוכן `web/` לשורש כתובת (או לתת-תיקייה: הנתיבים באתר יחסיים) ומגישים אותו. כרגע הוא מוגש מ-GitHub Pages: [deploy.yml](../.github/workflows/deploy.yml) מריץ `npm test` ורק אחריו מעלה את `web/`, בכל push ל-`main` שנוגע ב-`web/**`.
- **HTTPS הכרחי.** העתקת קישור ושיתוף (`navigator.clipboard`, `navigator.share`) עובדים רק בהקשר מאובטח.
- **סוג התוכן של קבצי `.mjs`** חייב להיות JavaScript (`text/javascript`). שרת שמחזיר להם `application/octet-stream` שובר את הסיור ואת ייבוא ה-PDF (ראו "אחרי כל פריסה").
- **מדיניות האבטחה (CSP) כתובה בתוך ה-HTML** (תג `<meta http-equiv="Content-Security-Policy">` ב-`index.html` וב-`legal.html`), ולכן אין צורך להגדיר כותרות בשרת. פירוט ב-[SECURITY](SECURITY.md).
- **מעבר לכתובת אחרת:**
  - מחליפים את הכתובת הקבועה ב-`web/index.html` (`og:url` ו-`og:image`, שורות 18 ו-21) ואת קישורי ה-issues ב-`web/index.html` וב-`web/legal.html`. בקבצי `web/*.js` הנתיבים יחסיים.
  - הבדיקה [test/app.test.mjs:164](../test/app.test.mjs) מקודדת את `https://dolev-benezri.github.io/lets_learn/og.png`. מעדכנים גם אותה, אחרת `npm test` והפריסה נכשלים.
  - הכתובת הישנה מופיעה גם ב-`README.md`, ב-`TERMS.md` וב-[.github/ISSUE_TEMPLATE/config.yml:4](../.github/ISSUE_TEMPLATE/config.yml).
  - ה-localStorage שייך לכתובת (origin), ולכן הנתונים ששמרו הסטודנטים **לא עוברים** לכתובת החדשה. לפני המעבר מבקשים מהם לייצא גיבוי (קישור גיבוי) ולפתוח אותו בכתובת החדשה.
- **נתונים:** הקבצים ב-`web/data/afeka/`. מי מייצר אותם: הסורק של המאגר (הריצה הלילית, בהמשך הדף), או ייצוא רשמי של המכללה.

## עדכון נתונים

1. **מהסורק:** הריצה הלילית בגיטלאב דוחפת קבצים חדשים ל-`web/data/afeka/`, ו-push כזה מפעיל פריסה. אין מה לעשות ביד.
2. **מייצוא רשמי:** מניחים את הקבצים בתיקייה נפרדת, במבנה של [DATA-CONTRACT](DATA-CONTRACT.md), ובודקים:

   ```
   npm run check:export -- <תיקיית הייצוא>
   npm run check:export -- <תיקיית הייצוא> --against web/data/afeka
   ```

   שגיאה (`ERROR:`) מחזירה קוד יציאה 1. אזהרה לא עוצרת. עם `--against` הבדיקה משווה לנתונים שעל האתר ומזהירה על ירידה חדה במספר הקורסים, הקבוצות והבחינות. כשהפלט הוא `ok` מעתיקים את התיקייה לתוך `web/data/afeka/`, מריצים `npm test` ופורסים.
3. האתר מבקש את הנתונים עם `cache: 'no-cache'` (בדיקת ETag), כך שגרסה חדשה מופיעה בביקור הבא בלי לנקות מטמון.

## web/settings.json

קובץ ההגדרות שמי שמחזיק את הכלי עורך ביד: [web/settings.json](../web/settings.json). האתר טוען אותו בכל כניסה ומנקה אותו שדה אחר שדה ב-`cleanSettings` ([web/settings.js](../web/settings.js)). שדה חסר או בסוג הלא נכון חוזר לברירת המחדל, ולכן קובץ שגוי לא שובר את האתר. מצד שני, ערך לא תקין פשוט **לא מוצג**, בלי הודעה. אחרי כל עריכה פותחים את האתר ובודקים שהערך מופיע.

הדוגמאות הן קטעים מתוך הקובץ; משלבים אותן באותו אובייקט. אחרי עריכה: `npm test` ([test/settings.test.mjs](../test/settings.test.mjs) קוראת את הקובץ), ואז commit ופריסה.

### notice: הודעה בראש האתר

טקסט חופשי שמופיע כרצועה אדומה (`role="alert"`) בראש האתר, לכל המשתמשים, עד שמרוקנים אותו. טקסט בלבד, בלי HTML. `""` מכבה אותה.

```json
{ "notice": "הנתונים של סמסטר ב׳ יתעדכנו מחר בבוקר" }
```

### turns: תורי הרשמה

רשימת התורים שהסטודנט בוחר ב"המצב שלי" ("התור שלי בהרשמה"). כשהתור שבחר כבר נפתח, והנתונים נמשכו לפני שנפתח, מוצגת האזהרה "הנתונים נמשכו לפני פתיחת התור שלך".

```json
{
  "turns": [
    { "id": "year-4", "label": "שנה ד׳", "opensAt": "2026-09-01T09:00:00+03:00" },
    { "id": "year-3", "label": "שנה ג׳", "opensAt": "2026-09-02T09:00:00+03:00" }
  ]
}
```

- `id`: מחרוזת עד 40 תווים. אל תשנו `id` אחרי שפורסם: הוא נשמר אצל הסטודנטים.
- `opensAt`: רגע עם אזור זמן (`+03:00` או `Z`), לא תאריך בלבד. תור בלי אזור זמן, בלי `id` או בלי `label` נזרק.
- בלי תורים אין בחירת תור ב"המצב שלי".

### supportEmail: כתובת לדיווח על טעות

כתובת אחת. מופיע קישור "דיווח על טעות" שפותח מייל עם התוכנית, המחזור, הסמסטר והקבוצה. ריק: אין קישור. הכלל ([web/settings.js:4](../web/settings.js)): כתובת אחת עם `@` אחד בדיוק, בלי רווח ובלי `< > " , % ? & #`, ולא בדומיין שמור לדוגמאות (`example.com`, `.test` וכדומה). כתובת שלא עומדת בו נפסלת בשקט.

```json
{ "supportEmail": "<כתובת התמיכה>" }
```

(בקובץ האמיתי מחליפים ב-`name@example.com` אמיתית.)

### counselingUrl: דף הייעוץ של המכללה

כתובת `https://` בלבד. מופיע קישור לייעוץ בתחתית האתר ובהערת התוצאות. ריק, `http://` או `javascript:`: אין קישור.

```json
{ "counselingUrl": "https://www.example.ac.il/counseling" }
```

### programs[id].approved: אישור מחלקה

`id` הוא מספר התוכנית (מפתח ב-[scripts/programs.json](../scripts/programs.json)), ובתוכו שנת מחזור ותאריך `YYYY-MM-DD`. לאותה תוכנית ומחזור מופיע "אושר על ידי המחלקה, 5.10.2026", והוא מסומן גם בדוח הכללים (בהמשך).

```json
{ "programs": { "30": { "approved": { "2026": "2026-10-05" } } } }
```

תאריך בפורמט אחר (`5.10.2026`, `2026-1-5`), חודש או יום מחוץ לטווח (`2026-13-01`) ושנה שאינה ארבע ספרות נזרקים. יום שאינו קיים בחודש (`2026-02-31`) לא נבדק, ובמנוע ה-JavaScript שבו נבדקה התוכנית הוא עובר; התוצאה תלויה במנוע ולכן אי אפשר לסמוך עליה. כותבים תאריך אמיתי.

### programs[id].conflicts: סתירות בין מקורות רשמיים

סתירה בין תוכנית הלימודים לידיעון. מופיעה ב"המצב שלי" למחזורים שברשימה, ומזינה את דפי הסתירות (`npm run report:conflicts`).

**דוגמה בלבד, לא להעתיק כמות שהיא:** המספרים והרשימה בדוגמה בדויים. כותבים סתירה אמיתית שנמצאה במקורות.

```json
{
  "programs": {
    "30": {
      "conflicts": [
        {
          "cohorts": [2026, 2027],
          "text": "נ״ז הבחירה (תוכנית הלימודים: 20, הידיעון: 18)",
          "plan": "20 נ״ז בחירה",
          "yedion": "18 נ״ז ברשימה 30009",
          "tool": "הולך לפי הידיעון: 18 נ״ז"
        }
      ]
    }
  }
}
```

- `cohorts`: רשימה לא ריקה של שנות מחזור (מספרים שלמים). `text`: עד 300 תווים, **בלי `.` `!` או `?` בסוף** (האתר מוסיף נקודה; הבדיקה ב-[test/settings.test.mjs:98](../test/settings.test.mjs) נכשלת אם `text` של סתירה בקובץ מסתיים באחד מהם). **סתירה שה-`text` שלה ארוך מ-300 תווים נזרקת כולה.**
- `plan`, `yedion`, `tool`: אופציונליים, עד 300 תווים כל אחד. ארוך מדי: רק העמודה נשמטת והסתירה נשארת. עמודה חסרה מודפסת בדף כ"לבדיקת המחלקה".
- כשהמחלקה מכריעה: מוחקים את הסתירה מהקובץ. הסתירות של שבע התוכניות שנשלחות היום (22, 20, 32, 12, 11, 112, 19) מוגנות בבדיקה ("the shipped settings.json" ב-[test/settings.test.mjs](../test/settings.test.mjs)), ומי שמוחק את כולן לתוכנית כזו מעדכן גם את הרשימה בבדיקה.

## בדיקות ודוחות

- `npm test`: בדיקות היחידה (`node --test "test/*.test.mjs"`). כוללות את הקריאה של `settings.json`, את מדיניות ה-CSP, את אורך השורות ב-`web/` (עד 200 תווים) ואת הסורק. חייב להיות ירוק לפני כל פריסה (גם `deploy.yml` מריץ אותו).
- `npm run test:browser`: דפדפן אמיתי (Playwright WebKit): נגישות (axe), זרימות מלאות והסיור. דורש `npm ci` והתקנת הדפדפן של Playwright.
- `npm run report:rules`: דף A4 לכל תוכנית ומחזור עם הרשימות, הנ״ז ודרישות הקדם שהכלי קורא, וקו חתימה למחלקה, ב-`out/rules/` (`index.html` הוא התוכן). קורא רק את `web/data/afeka/` ואת `settings.json`, בלי רשת.
- `npm run report:conflicts`: דף אחד לכל מחלקה שיש לה סתירה פתוחה, ב-`docs/conflicts/<מספר מחלקה>.html` (נשמר ב-git, כדי לעקוב אחרי הפערים עד שהמחלקה עונה), עם עמודה ריקה להחלטה. נבנה מ-`programs[id].conflicts`.
- התיקייה `out/` לא נכנסת ל-git (`.gitignore`). פותחים את הקובץ בדפדפן ומדפיסים.

## אחרי כל פריסה

מחליפים `<site>` בכתובת האתר:

1. הדף עולה, ואין בו רצועה אדומה (`notice`) שלא תכננתם.
2. `curl -s <site>/settings.json` מחזיר את הקובץ שערכתם.
3. `curl -I <site>/vendor/driver/driver.js.mjs` חייב להחזיר `200` ו-`Content-Type` של JavaScript (`text/javascript` או `application/javascript`). אחרת הסיור נעלם בשקט: אין שגיאה, פשוט אין סיור ([web/tour.js](../web/tour.js) מדלג עליו כשהמודול לא נטען). לאותה סיבה בודקים גם `<site>/vendor/pdfjs/pdf.min.mjs` (ייבוא ציונים).
4. `curl -I <site>/data/afeka/catalog.json` מחזיר `200`.
5. בדפדפן: בוחרים תוכנית ומחזור, ורואים קורסים ולוח.

## הריצה הלילית

**הריצה הלילית הראשונה:** המטמון של GitLab ריק בהתחלה, ומשיכה מלאה ארוכה מריצה אחת. `timeout 160m` עוצר את הסורק לפני ש-GitLab הורג את ה-job, המטמון נשמר (`when: always`), והריצה נחשבת חלקית: ירוקה, בלי commit. הריצה הבאה ממשיכה מהמטמון, ולכן משיכה ראשונה לוקחת 2-3 לילות. הריצה החלקית הרביעית ברצף נכשלת, כדי שסריקה תקועה תשלח מייל.

**דקות CI:** בחשבון החינמי של GitLab יש לקבוצה 400 דקות CI בחודש, גם לפרויקט ציבורי (מקדם 1; רק תוכנית GitLab for Open Source מורידה ל-0.5). ההשהיה בין בקשות נספרת כזמן ריצה. משיכת כל הקבוצות בכל לילה לקחה כ-20 דקות, כלומר כ-600 בחודש, ולכן כל קורס נמשך פעם בשני לילות: כ-11 דקות ללילה, כ-330 בחודש. הקבוצות באתר בנות יום או יומיים לכל היותר. הפרויקט `lets_learn-group/lets_learn-scrape` ציבורי, ולכן לוגי הריצות גלויים: הטוקן לא מודפס בהם, ומשתני ה-CI נשארים סודיים.

## חידוש GH_PUSH_TOKEN

הסריקה דוחפת ל-GitHub עם טוקן fine-grained שיש לו תאריך תפוגה. ה-job `token-expiry` ב-[ci/gitlab-scrape.yml](../ci/gitlab-scrape.yml) נכשל, ושולח מייל, כשנשארים פחות מ-14 יום, וגם כש-GitHub דוחה את הטוקן (פג או בוטל). הסריקה עצמה ממשיכה לרוץ. כדי לחדש:

1. ב-GitHub: Settings → Developer settings → Fine-grained tokens → Generate new token.
2. Repository access: רק `dolev-benezri/lets_learn`. Permissions: Contents, Read and write. לבחור תאריך תפוגה.
3. ב-GitLab, בפרויקט `lets_learn-scrape`: Settings → CI/CD → Variables → `GH_PUSH_TOKEN` → להדביק את הטוקן החדש (Masked and hidden, Protected).
4. Build → Pipeline schedules → ▶ כדי להריץ פעם אחת. ב-log של `token-expiry` מופיע התאריך החדש.
5. למחוק ב-GitHub את הטוקן הישן.

## מעבר שנת לימודים

האתר לוקח את השנה האקדמית מ-`catalog.json`, שהסורק כותב, והמטמון נשמר בתיקייה נפרדת לכל שנה (`.yedion-cache/2028`). כשהידיעון של השנה הבאה מתפרסם:

1. משנים את ברירת המחדל של `--year` ב-`scripts/scrape.mjs`.
2. ב-`scripts/programs.json`, לכל תוכנית: מוסיפים את המחזור החדש ל-`cohorts` ואת קודי הרשימות שלו ל-`lists`, ומורידים את המחזור הישן.
3. ב-`web/ics.js` מוסיפים ל-`SEMESTER_DATES` את תאריכי הסמסטרים ואת הימים בלי לימודים, מתוך [לוח השנה האקדמי](https://www.afeka.ac.il/about-afeka/general-information/academic-calendar/). בלי השורה הזו, כפתור הייצוא ללוח שנה כבוי.
4. מריצים `npm test` ומחכים לריצה הלילית. קישורי גיבוי מהשנה הקודמת ממשיכים לעבוד: הקורסים, הציונים וההעדפות נשמרים, ונעיצות, חברים ושיוך לסמסטר נמחקים. קישורי חבר מהשנה הקודמת נדחים.

## הוספת תוכנית

1. `node scripts/discover.mjs --cache cache --offline > draft.json` מפיק טיוטת הגדרות מהמטמון: מסלולים, מחזורים, רשימות והתמחויות.
2. מעתיקים את הטיוטה ל-`scripts/programs.json` ומשלימים ידנית את מה שלא מופיע באתר: `deptName` (מילת האוכלוסייה בדרישות הקדם), `anchor` (קורס שחייב להופיע בכל מחזור וסמסטר), `degree`, `specRule`, ולפעמים `minCourses` לתוכנית קטנה.
3. משאירים `verified: false` עד שכל שדה שמולא ביד נבדק מול תוכנית הלימודים הרשמית של התוכנית, ומוסיפים את הקישור אליה ל-[COVERAGE](COVERAGE.md).
4. מריצים `npm test` ו-`--offline` על המטמון, ובודקים בדפדפן.
5. `node scripts/audit.mjs` מדפיס סקירת נתונים אוטומטית (קורסי חובה שלא נפתחים, דרישות קדם שבורות, סכומי נ״ז). הדוח האחרון: [docs/DATA-AUDIT.md](DATA-AUDIT.md).
