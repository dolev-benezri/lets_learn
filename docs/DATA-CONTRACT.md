# חוזה הנתונים

האתר קורא קבצי JSON סטטיים מהתיקייה `web/data/afeka/`. אין שרת ואין API. מי שמספק את הקבצים (הסקרייפר שבמאגר, או ייצוא רשמי של המכללה) צריך לעמוד במבנה שבדף הזה.
הבדיקה האוטומטית: `npm run check:export -- <תיקייה>` ([scripts/check-export.mjs](../scripts/check-export.mjs), הבדיקות ב-[test/check-export.test.mjs](../test/check-export.test.mjs)).

## מבנה התיקייה

```
afeka/
  catalog.json            רשימת התוכניות והמחזורים (חובה)
  status.json             מתי נבדק לאחרונה (חובה)
  2027-1/30-2026.json     שנה 2027, סמסטר א׳, תוכנית 30, מחזור 2026 (חובה לכל תוכנית ומחזור ב-catalog)
  2027-2/30-2026.json     סמסטר ב׳ (אם חסר: האתר מתכנן סמסטר אחד ומציג הודעה)
  2027-3/30-2026.json     קיץ (אם חסר: אין אפשרות לתכנן קיץ)
```

שם קובץ הנתונים: `<שנה>-<1|2|3>/<מספר תוכנית>-<שנת התחלה>.json` ([web/app.js:164](../web/app.js)). `1` = א׳, `2` = ב׳, `3` = קיץ.
קובץ שאינו מופיע ב-`catalog.json` לא נטען אף פעם, והבודק מזהיר עליו.

## catalog.json

| שדה | סוג | חובה | מה האתר עושה בלעדיו |
|---|---|---|---|
| `year` | מספר שלם | כן | הקובץ נחשב פגום |
| `programs[].id` | מספר שלם | כן | התוכנית נפסלת, ואם אין אחת תקינה האתר חוזר לברירת המחדל (הנדסת מכונות 2026) |
| `programs[].name` | טקסט | כן | כנ״ל |
| `programs[].startYears` | רשימת מספרים שלמים | כן | כנ״ל |

דוגמה: `{ "year": 2027, "programs": [{ "id": 30, "name": "הנדסת מכונות", "startYears": [2024, 2025, 2026, 2027] }] }`.
האתר מוודא את הצורה ב-`goodCatalog` ([web/app.js:22](../web/app.js)). תוכנית דו-שנתית או מחזור שירד נשארים מחוץ ל-`startYears`, ואין צורך לספק להם קבצים.

## status.json

| שדה | סוג | חובה | מה האתר עושה בלעדיו |
|---|---|---|---|
| `checkedAt` | תאריך ISO | כן | שורת הטריות בכותרת כותבת "לא ידוע מתי נבדק" ([web/ui-text.js](../web/ui-text.js), `freshness`) |
| `ok` | true / false | לא (הבודק מזהיר) | חסר או `false`: שורת הטריות מסומנת כישנה (`!status.ok` ב-`freshness`) |
| `semesters` | אובייקט | לא | האתר לא קורא אותו; הסקרייפר שומר בו גיבוב לכל קובץ כדי לדעת מה השתנה |

## קובץ נתונים, שדה אחר שדה

"חובה" = חסר הוא שגיאה בבודק. שדות לא מוכרים אינם שגיאה (הבודק והאתר מתעלמים מהם).

### ראש הקובץ

| שדה | סוג | חובה | דוגמה | מה האתר עושה בלעדיו |
|---|---|---|---|---|
| `year`, `startYear`, `program` | מספר שלם | כן | `2027`, `2026`, `30` | חייבים להתאים לנתיב ול-catalog (הבודק בודק) |
| `semester` | `"א"` / `"ב"` / `"קיץ"` | כן | `"א"` | חייב להתאים לתיקייה |
| `examsPublished` | true / false | כן | `false` | `false`: האתר כותב "לוח הבחינות טרם פורסם" ולא מחשב מרווחי בחינות |
| `lists` | רשימה | כן | ראו למטה | אין רשימות קורסים, אין מפת התקדמות |
| `courses` | אובייקט לפי מספר קורס | כן | ראו למטה | אין קורסים |
| `fetchedAt` | תאריך ISO | לא | `"2026-10-16T18:08:48Z"` | כותרת הדף כותבת "השתנה לאחרונה" בלי תאריך תקין. אצלנו: מועד השינוי האחרון בקובץ |
| `specializations` | רשימה | לא | `{ "id": "tech", "name": "…", "mandatory": [10101], "elective": 10102 }` | אין בחירת התמחות ([web/rules.js](../web/rules.js)) |
| `specRule` | אובייקט | לא | `{ "pick": 1 }` | ברירת מחדל: בוחרים שתיים ([web/rules.js:16](../web/rules.js)) |
| `degree` | אובייקט | לא | `{ "total": 160 }` | אין "נ״ז עד סיום התואר" במפה |
| `verified` | false | לא | `false` | `false` מציג "הנתונים עוד לא נבדקו מול תוכנית הלימודים". חסר = לא מוצג כלום |

### `lists[]` (רשימות קורסים: חובה, בחירה וכו׳)

| שדה | סוג | חובה | דוגמה |
|---|---|---|---|
| `code` | מספר שלם | כן | `30001` |
| `name` | טקסט | כן | `"קורסי חובה שנה א'"` |
| `minCredits` | מספר | כן | `41` |
| `courses` | רשימת מספרי קורס | כן | `["10016", "30003"]`. כל מספר חייב להופיע ב-`courses` |

### `courses.<מספר קורס>`

| שדה | סוג | חובה | דוגמה | מה האתר עושה בלעדיו |
|---|---|---|---|---|
| `name` | טקסט | כן | `"פיזיקה-מכניקה"` | הקורס לא נטען |
| `credits` | מספר | כן | `5` | `0` נספר כאפס נקודות; הבודק מזהיר כשקורס שנפתח הוא `0` (בדרך כלל כשל בקריאת הנתונים) |
| `offered` | true / false | כן | `true` | `false`: אפשר לסמן שעברו אותו אבל לא לשבץ אותו |
| `prereqs` | רשימה | כן (יכולה להיות ריקה) | ראו למטה | אין חסימות לפי דרישות קדם |
| `groups` | רשימה | כן (יכולה להיות ריקה) | ראו למטה | הקורס לא ניתן לשיבוץ |

`prereqs[]`: `{ "kind": "קדם", "anyOf": [{ "id": "6000", "name": "אנגלית טרום בסיסי" }] }`. כל פריט ב-`anyOf` מספיק. `id` יכול להיות `null` כשהקורס אינו בתוכנית (האתר מחשיב אותו כמתקיים).

### `groups[]` (קבוצה = הרצאה, תרגול, מעבדה)

| שדה | סוג | חובה | דוגמה | מה האתר עושה בלעדיו |
|---|---|---|---|---|
| `id` | טקסט | כן | `"279090303"`, תת-קבוצה `"279090303/1"` | מזהה את הקבוצה בסימון, בקישורים וב-`.ics`. חייב להיות קבוע בין עדכונים |
| `type` | טקסט | כן | `"סופי-הרצאה+תרגול"` | מוצג למשתמש |
| `primary` | true / false | כן | `true` | קבוצה ראשית משובצת בעצמה; תת-קבוצה (תרגול, מעבדה) נבחרת מתוך `linked` של קבוצה ראשית ([web/solver-core.js:68](../web/solver-core.js)) |
| `lecturer` | טקסט (יכול להיות ריק) | כן | `"ד״ר …"` | נראה כריק |
| `full` | true / false | כן | `false` | `true`: מסומנת "מלאה", ולא משובצת אלא אם המשתמש כלל קבוצות מלאות או נעץ אותה ([web/solver-core.js:78](../web/solver-core.js)) |
| `semester` | טקסט | כן | `"א"` | |
| `linked` | רשימת מזהים | כן | `["279090303/1"]` | תת-קבוצה שאף קבוצה ראשית לא מקשרת אליה לא תשובץ אף פעם (הבודק מזהיר) |
| `meetings` | רשימה | כן | ראו למטה | חסר = שגיאה: הקבוצה לא ניתנת לשיבוץ. קבוצה בלי מפגשים (מקוונת) נשמטת בסקרייפר |
| `exams` | רשימה | כן (יכולה להיות ריקה) | ראו למטה | |
| `seatsLeft` | מספר שלם ≥ 0 | לא, חדש | `12` | ראו "שדות חדשים" |
| `fetchedAt` | תאריך ISO | לא, חדש | `"2026-10-16T18:08:48Z"` | ראו "שדות חדשים" |

`meetings[]`: `{ "day": 1, "start": "17:00", "end": "19:50", "room": "115 פיקוס" }`. `day` = 1 עד 6, א׳ עד ו׳. שעות בפורמט `HH:MM`, בין 07:00 ל-23:00, והתחלה על :00 או :30 (הלוח של האתר בנוי בחצאי שעה, `validate` ב-[scripts/build.mjs:102](../scripts/build.mjs)). `room` רשות.
`exams[]`: `{ "kind": "בחינה", "moed": 1, "date": "2027-02-04", "time": "09:00" }`. התאריך חייב ליפול בשנת הלימודים של הקובץ (מ-1.9 של השנה הקודמת עד 30.9).

## שדות חדשים לייצוא רשמי

- `groups[].seatsLeft`: כמה מקומות נשארו בקבוצה. אופציונלי; הבודק מקבל אותו רק כמספר שלם אי-שלילי.
- `groups[].fetchedAt`: מתי הנתון של הקבוצה הזו נמשך. אופציונלי.

שניהם אופציונליים בכוונה: ייצוא בלעדיהם תקין. נכון לקומיט הזה האתר עדיין לא קורא אותם (`grep seatsLeft web/` ריק), כך שאין להם השפעה על המסך עד שנוסף להם שימוש.

## איך בודקים ייצוא

```
npm run check:export -- <תיקיית הייצוא>
npm run check:export -- <תיקיית הייצוא> --against web/data/afeka
```

הבדיקה:
1. `catalog.json` ו-`status.json` קיימים ותקינים.
2. לכל תוכנית ומחזור ב-catalog יש קובץ לסמסטר א׳ (שגיאה אם חסר), ולסמסטרים ב׳ וקיץ (אזהרה אם חסר).
3. כל שדה חובה קיים ובסוג הנכון, והשגיאה מציינת את הנתיב המלא, למשל `2027-1/30-2026.json: courses.20816.groups[0].meetings: missing`.
4. הקובץ מתאים לנתיב שלו ול-catalog, וכל קורס ברשימה קיים ב-`courses`.
5. אותן בדיקות בריאות של `validate` ([scripts/build.mjs:68](../scripts/build.mjs)) שהסקרייפר מריץ: מפגש בלי יום, שעות לא סבירות, תאריך בחינה מחוץ לשנה, קדם שמצביע על הקורס עצמו.
6. עם `--against`: `compareToPrevious` ([scripts/build.mjs:134](../scripts/build.mjs)) משווה לנתונים הקיימים באתר ומזהיר על ירידה חדה במספר הקורסים, הקבוצות, המפגשים והבחינות.

שגיאה מחזירה קוד יציאה 1. אזהרה לא עוצרת; היא מסמנת משהו שכדאי לבדוק (אצלנו, למשל, תת-קבוצות שלא מקושרות לקבוצה ראשית).
